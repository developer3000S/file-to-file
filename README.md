# File-to-File Converter

Утилита командной строки для конвертации файлов между различными форматами.

## Поддерживаемые форматы

### Входные форматы
- PDF (.pdf)
- DOCX (.docx)
- XLSX (.xlsx)
- Markdown (.md, .markdown)

### Выходные форматы
- Markdown (.md)
- PDF (.pdf)
- DOCX (.docx)
- XLSX (.xlsx)

## Поддерживаемые конвертации

Все 12 пар между четырьмя форматами:

- `.pdf`  → `.docx`, `.xlsx`, `.md`
- `.docx` → `.pdf`,  `.xlsx`, `.md`
- `.xlsx` → `.pdf`,  `.docx`, `.md`
- `.md`   → `.pdf`,  `.docx`, `.xlsx`

## Установка зависимостей

Для работы утилиты требуются следующие зависимости:

```bash
# Для конвертации PDF
sudo apt-get install poppler-utils # содержит pdftotext, pdffonts, pdftoppm
# или
sudo apt-get install mupdf # содержит mutool

# Для конвертации отсканированных PDF (без текстового слоя)
# Такие PDF содержат только изображения, поэтому текст извлекается через OCR.
sudo apt-get install tesseract-ocr        # сам движок OCR
sudo apt-get install tesseract-ocr-rus    # языковые данные для русского
# Проверить, что языки на месте:
tesseract --list-langs

# Для конвертации DOCX и других форматов
sudo apt-get install pandoc

# Для конвертации в XLSX
pip install --user pandas openpyxl --break-system-packages
# или установите через apt, если доступны пакеты
sudo apt-get install python3-pandas python3-openpyxl

# Для конвертации в PDF (нужен LaTeX-движок: xelatex или pdflatex)
# Внимание: xelatex и pdflatex — это программы, а не имена пакетов.
# `apt-get install xelatex` или `apt-get install pdflatex` завершится ошибкой
# "Unable to locate package". Устанавливать нужно пакеты texlive-*:
sudo apt-get install texlive-xetex        # содержит xelatex
sudo apt-get install texlive-latex-base   # содержит pdflatex
# и пакеты, без которых движок не соберёт документ:
sudo apt-get install texlive-fonts-recommended texlive-latex-extra
sudo apt-get install texlive-lang-cyrillic    # кириллица в PDF

# Проверить, что движки на месте:
which xelatex pdflatex
```

## Альтернативный способ установки Python-пакетов

Если возникают проблемы с установкой системных пакетов из-за PEP 668, можно использовать виртуальное окружение:

```bash
# Создание виртуального окружения
python3 -m venv venv
source venv/bin/activate
pip install pandas openpyxl
```

Или использовать pipx для установки приложений:

```bash
# Установка pipx
sudo apt-get install pipx
# Установка пакетов через pipx
pipx install pandas openpyxl
```

## Компиляция

```bash
make
```

Программа собирается из нескольких модулей (см. «Структура проекта» ниже).
Флаги `-Wall -Wextra -std=c11` включены; сборка не выдаёт предупреждений.

## Установка

```bash
sudo make install     # копирует бинарник в /usr/local/bin
sudo make uninstall   # удаляет его
```

## Использование

```bash
# Конвертация одного файла (формат задаётся расширением)
./file-to-file <входной_файл> <выходной_файл>

# Пакетная конвертация всех файлов в каталоге
./file-to-file <входной_каталог> <выходной_каталог> <формат>
```

### Опции командной строки

| Ключ              | Действие                                    |
|-------------------|---------------------------------------------|
| `-v`, `--verbose` | подробный вывод (уровень DEBUG)             |
| `-q`, `--quiet`   | только ошибки (уровень ERROR)               |
| `-h`, `--help`    | справка со списком всех конвертаций         |

Примеры:
```bash
# Одиночные файлы
./file-to-file document.pdf document.md
./file-to-file document.docx document.pdf
./file-to-file table.xlsx table.docx

# Подробный вывод при конвертации
./file-to-file -v big_scan.pdf out.docx

# Только ошибки (удобно в скриптах)
./file-to-file -q ./docs ./docs_md md

# Батч-режим: конвертировать все файлы в папке
./file-to-file ./documents ./output pdf
./file-to-file ./spreadsheets ./markdown md
```

## Структура проекта

Код разбит на независимые модули; все объявления собраны в `utils.h`.

| Файл        | Назначение                                                        |
|-------------|------------------------------------------------------------------|
| `main.c`    | разбор аргументов, маршрутизация конвертаций, батч-режим, справка |
| `utils.c`   | запуск внешних команд (`fork`+`execvp`), приватный рабочий каталог, поиск утилит в PATH |
| `log.c`     | уровни логирования и прогресс-бар (TTY-only)                     |
| `pdf.c`     | извлечение текста из PDF, детект сканов, `pdf → md/docx/xlsx`    |
| `ocr.c`     | OCR отсканированных PDF через Tesseract + кэш результатов        |
| `pandoc.c`  | все маршруты через pandoc (`md`/`docx`/`pdf`)                    |
| `xlsx.c`    | чтение/запись XLSX через python3 (openpyxl + pandas)             |
| `table.c`   | разбор и запись CSV (RFC 4180) и markdown-таблиц                 |

## Особенности реализации

Программа использует внешние утилиты для конвертации файлов:
- `pdftotext` или `mutool` для извлечения текста из PDF;
- `tesseract` для отсканированных PDF (см. ниже);
- `pandoc` для конвертации между документами;
- `python3` + `pandas` + `openpyxl` для XLSX.

Вместо `system()` используется `fork` + `execvp` для предотвращения инъекций
через имена файлов (в том числе содержащих `;`, `$(...)`, обратные кавычки).

Временные файлы создаются в приватном каталоге `$TMPDIR/file-to-file-*`,
который удаляется автоматически при завершении программы (через `atexit`).

### Отсканированные PDF

Некоторые PDF не содержат текстового слоя — это фотографии страниц. `pdftotext`
из такого файла возвращает практически пустой результат, и обычная конвертация
дала бы пустой документ.

Программа определяет это автоматически: перед извлечением текста запускается
`pdftotext`, и если остаётся меньше трёх непустых строк, PDF считается сканом.
Для таких файлов вместо `pdftotext`/`mutool` запускается OCR-конвейер:

1. `pdftoppm -r 200 -png` растрирует страницы во временный каталог;
2. имена полученных изображений собираются в список и сортируются,
   так как `pdftoppm` дополняет номера страниц нулями до ширины общего
   числа страниц (`pg-1.png`, `pg-01.png`, `pg-001.png`);
3. `tesseract <список> text -l rus+eng --psm 6` распознаёт все страницы
   в один текстовый файл.

Дальше текст идёт по обычной цепочке `pdf -> md -> docx`. Поведение прозрачно
для вызывающего: `./file-to-file scan.pdf scan.docx` работает так же, как для
PDF с текстовым слоем, только медленнее. Если `tesseract` не установлен,
программа сообщит об этом и не станет выдавать пустой документ.

Распознавание сканов заметно медленнее обычного извлечения текста и даёт
ошибки в мелком шрифте, колонтитулах и таблицах — это ограничение OCR,
а не конвертера.

### Кэш OCR

Распознавание одного и того же скана повторно запускается не всегда: результат
OCR кэшируется на диске и переживает завершение процесса.

- Ключ кэша — `FNV-1a` от строки `<абсолютный_путь>|<размер>|<mtime>`, поэтому
  изменённый файл (другой размер или время модификации) автоматически уходит в
  новый проход, а старый кэш остаётся неактуальным.
- По умолчанию кэш лежит в `$XDG_CACHE_HOME/file-to-file/ocr/`, при отсутствии
  `XDG_CACHE_HOME` — в `$HOME/.cache/file-to-file/ocr/`.
- Каталог можно переопределить переменной окружения `FF_OCR_CACHE_DIR`.

### Ограничения

- `pandoc` с `markdown` reader падает (OOM) на больших OCR-текстах. Для
  `md → docx` и `md → pdf` используется reader `gfm`, который этого не делает.
- `pandoc` не умеет писать XLSX, поэтому все маршруты в XLSX идут через
  разбор markdown-таблицы в CSV (RFC 4180) и запись `pandas`.
- `pandoc` требует `xelatex` или `pdflatex` для вывода PDF.
- `tesseract` требует языковые данные `rus` и `eng`.

## Батч-режим

Для пакетной конвертации всех файлов в каталоге используйте:

```bash
./file-to-file <входной_каталог> <выходной_каталог> <формат>
```

Пример:
```bash
# Конвертировать все файлы в папке ./docs в PDF
./file-to-file ./docs ./docs_pdf pdf
```

Батч-режим:
- Обрабатывает только обычные файлы в указанном каталоге (не рекурсивно).
- Пропускает файлы без поддерживаемых расширений.
- Файлы, требующие реальной конвертации, сохраняются как
  `<имя>_<исходный_формат>.<целевой>` (например `tab_docx.md`), чтобы не
  сталкиваться с одноимёнными файлами из других исходных форматов.
- Файл, уже находящийся в целевом формате, копируется как `<имя>.<целевой>`.
- Отклоняет одинаковые входной и выходной каталоги.
- Создаёт выходной каталог при необходимости.
- В конце печатает итог: `N конвертировано, M ошибок, K пропущено`.

## Тестирование

Для проверки корректности работы программы созданы тестовые файлы и скрипт
автоматического тестирования `Sample/run_tests.sh`. Он покрывает все 12
конвертаций, round-trip запятой внутри ячеек, защиту от инъекций через имя
файла, уборку временных каталогов, поведение CLI и батч-режим.

Чтобы запустить тесты:

```bash
make check
# или напрямую:
cd Sample && ./run_tests.sh
```

Скрипт выходит с ненулевым кодом, если что-то не сработало, поэтому его можно
использовать в CI.
